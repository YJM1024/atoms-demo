# Atoms Demo · 多智能体应用生成工作台

[在线体验](https://motes-yjm.pub.atoms.world) · [Atoms 开发项目](https://atoms.dev/chat/567b7c0d158041478a6c5c48774c3d1b?block=Editor)

用自然语言描述需求，由产品经理、架构师和工程师分步生成网页应用，在右侧实时预览；之后可以继续提出修改意见，查看版本差异、回滚、分享或下载代码。

这是基于 Atoms 构建的产品原型。本文按当前源码说明实现方式、完成范围和后续优先级。

## 体验方式

1. 打开在线 Demo，输入需求或选择示例；生成和保存项目需要登录 Atoms 账号。
2. 查看需求拆解、技术方案、代码生成及自动检测过程，在预览区操作生成的应用。
3. 继续输入修改意见，例如“把按钮改成蓝色”，再体验版本对比、回滚、公开分享和 ZIP 导出。

## 实现思路与关键取舍

前端使用 React 18、TypeScript、Vite、Tailwind CSS 和 shadcn/ui；后端使用 FastAPI，复用 Atoms Cloud 的认证、数据库和 Web SDK。

生成流程为“产品经理 → 架构师 → 工程师 → 测试程序”。前三个角色通过不同提示词调用真实模型，串行传递结果；测试程序执行确定性检查。迭代修改时跳过架构师。模型由后端统一代理，DeepSeek 密钥由部署者配置在后端环境变量中。

| 设计选择 | 原因与代价 |
| --- | --- |
| 前端编排、流式展示 | 便于实时显示过程并调用浏览器检测；刷新或关闭页面后不能后台续跑。 |
| 生成单文件 HTML/CSS/JS | 无需构建即可预览，修改、对比和导出简单；暂不支持多文件、框架项目或生成应用的后端。 |
| SEARCH/REPLACE 增量补丁 | 减少无关改动；匹配失败时回退到整体重写。目前未强制校验唯一匹配。 |
| 沙箱预览与自动检测 | iframe 不开放同源权限；检查结构、语法、运行异常及基本交互，发现问题后最多自动修复 3 轮。检测通过不代表业务逻辑正确。 |

主要逻辑位于 `app/frontend/src/lib/pipeline.ts`、`agents.ts`、`patch.ts` 和 `tester.ts`；模型代理位于 `app/backend/services/agent_llm.py`。

## 当前完成程度

| 能力 | 当前实现 |
| --- | --- |
| 生成与迭代 | 分角色流式输出、实时预览、代码视图；支持增量修改、整体重写回退和截断续写。 |
| 检测与修复 | 静态检查、隐藏 iframe 运行探针、交互冒烟、自动修复；未通过的结果会保留失败标记。 |
| 项目与版本 | 数据库保存项目、对话和版本；支持重新打开、重命名、删除、diff 和回滚。 |
| 版本规则 | 一轮生成与自动修复结束后保存一个版本；回滚另存新版本；“再次自动修复”更新当前版本。 |
| 分享与导出 | 随机链接公开预览项目当前代码，可停止分享；ZIP 包含当前 HTML、版本快照和说明。 |
| 账号与界面 | Atoms 登录、登出、个人项目入口；响应式布局和窄屏聊天／预览切换。 |

当前边界与待完善项：

- **权限与用量保护**：普通项目接口按用户过滤，但模板中的全量查询入口及 AI 调用入口尚未统一鉴权、限流；数据库未配置 RLS，不能视为生产级隔离。
- **保存一致性**：版本快照和项目当前状态分两次请求保存，版本号由前端计算，尚未处理完整的事务与并发冲突。
- **运行与数据**：预览注入内存 Storage，刷新后应用内部数据会丢失；工作台的项目和版本则保存到数据库。外部资源主要通过提示词约束和检测提示限制。
- **验证范围**：导出包保留了生成、增量修改和版本规则的历史报告；部分测试使用内存快照，未覆盖真实登录、写库及全部页面操作。验证脚本依赖平台路径，`fix_loop.py` 的调用参数还需与当前实现对齐，不能直接视为本版完整验收通过。

## 继续投入时间的优先级

1. **P0：完善安全与交付验证。** 收紧全量查询和 AI 接口权限，增加基础限流；修正验证脚本，跑通登录、生成、修改、真实保存、刷新恢复、分享及导出。
2. **P1：提升修改与保存可靠性。** 补丁必须唯一命中；由后端事务保存版本并处理并发；增加业务结果断言、取消生成和用量统计。
3. **P2：扩大能力边界。** 增加后台任务与恢复，再支持多文件工程和模型选择。先保证现有流程稳定，再增加会影响预览、检测和导出的复杂能力。

## 运行与目录

`app/frontend/` 为前端，`app/backend/` 为后端，`scripts/verify/` 为验证脚本，`.atoms/` 为开发过程中的架构与进度记录。

在 Atoms 内使用平台提供的运行环境。脱离平台运行时，需要自行提供认证、数据库和 SDK 对应配置；完整的独立部署尚未验证。

```bash
# 后端：先配置认证、数据库及模型所需环境变量
cd app/backend
pip install -r requirements.txt
uvicorn main:app --host 0.0.0.0 --port 8000

# 前端：另开终端，从项目根目录执行
cd app/frontend
pnpm install
pnpm run dev
# 静态检查与构建
pnpm run lint
pnpm run build
```

模型配置至少需要 `DEEPSEEK_API_KEY`；`DEEPSEEK_MODEL`、`DEEPSEEK_FALLBACK_MODEL` 等配置及默认值见 `app/backend/services/agent_llm.py`。密钥、环境文件、运行日志和构建产物不纳入仓库。
