# Atoms Demo · 多智能体应用生成工作台

[在线体验](https://motes-yjm.pub.atoms.world) · [GitHub 源码](https://github.com/YJM1024/atoms-demo) · [Atoms 开发项目](https://atoms.dev/chat/567b7c0d158041478a6c5c48774c3d1b?block=Editor)

用一句话生成可交互的网页应用，再通过对话继续修改、对比版本、回滚和分享。产品经理拆解需求，架构师给出方案，工程师流式写入代码；测试程序在沙箱中检查运行情况，并将问题交回工程师自动修复。

本项目聚焦一条完整体验：**描述需求 → 分角色生成 → 检测与修复 → 可视化预览 → 持续修改 → 保存与带走结果**。

## 快速体验

![在线首页：需求输入与示例入口](docs/images/homepage.jpg)

首页可直接浏览；生成与项目管理需要登录 Atoms 账号。公开分享页无需登录，可以操作生成的应用。

建议按下面这条路径体验：

1. **生成应用**：输入“做一个待办清单，支持添加、完成、删除和状态筛选”，发送后查看角色输出、代码写入和检测报告。
2. **操作与修改**：在右侧预览中操作应用，再输入“把所有按钮改成蓝色”，观察增量修改和预览更新。
3. **对比与恢复**：到“版本”页比较两次结果；回滚会另存一个新版本，原有历史仍保留。
4. **分享与导出**：创建公开只读分享链接，或复制代码、下载 HTML、导出含版本快照的 ZIP。

## 当前完成程度

| 能力 | 已实现内容 |
| --- | --- |
| 真实生成与过程展示 | 三个模型角色串行协作，流式显示需求、方案和代码；预览随代码节流刷新。 |
| 多轮迭代 | 优先使用 SEARCH/REPLACE 补丁；定位失败时回退到整体重写，输出截断时尝试续写。 |
| 检测与自动修复 | HTML 结构、脚本语法、运行异常和基本交互检查；最多自动修复 3 轮，仍未通过时保留失败标记。 |
| 项目与版本 | 数据库保存项目、对话和代码快照；支持重新打开、重命名、删除、版本 diff 和回滚。 |
| 结果交付 | HTML 下载、代码复制、ZIP 导出，以及可停止分享的公开预览链接。 |
| 账号与界面 | Atoms 登录与登出、个人项目入口、响应式布局和窄屏聊天／预览切换。 |

**验证范围**：仓库保留了[历史生成与修改记录](scripts/verify/out/)，覆盖待办、计算器、贪吃蛇及按钮改色。部分验证使用内存版本存储；真实登录、数据库保存及分享导出的整站回归仍待补齐，历史报告不等于当前版本的完整验收。

**当前范围与边界**：

- 生成目标是单文件 HTML/CSS/JS；多文件工程、npm 依赖和生成应用的后端尚未支持。工作台的项目与版本会保存到数据库，预览内的应用数据采用内存 Storage，刷新后清空。
- 接口权限与限流仍需加固，尤其是模板全量查询和 AI 调用入口；补丁唯一匹配、版本事务及并发冲突处理待完善。

## 实现思路与关键取舍

前端采用 React 18、TypeScript、Vite、Tailwind CSS 和 shadcn/ui；后端采用 FastAPI，复用 Atoms Cloud 的认证、数据库和 Web SDK。模型通过后端统一代理，DeepSeek 密钥由部署者配置在环境变量中。

| 关键选择 | 实现理由与取舍 |
| --- | --- |
| 前端编排 | 将角色输出、预览和浏览器检测串在同一流程中，便于快速实现实时反馈；关闭页面后无法后台续跑。 |
| 单文件应用与增量补丁 | 无需在线构建即可运行，版本对比、分享和导出都围绕同一份代码；补丁失败时以整体重写兜底。 |
| 确定性检测与限次修复 | 测试角色由规则和浏览器运行探针实现，结果可追溯、修复次数有上限；当前主要检测异常，尚不能证明业务结果正确。 |
| 草稿与版本分离 | 一轮生成及自动修复结束后保存一个版本，减少中间快照；回滚另存新版本，“再次自动修复”则更新当前版本。 |

实现入口：[`pipeline.ts`](app/frontend/src/lib/pipeline.ts) 负责流程编排，[`patch.ts`](app/frontend/src/lib/patch.ts) 负责补丁应用，[`tester.ts`](app/frontend/src/lib/tester.ts) 负责检测，[`agent_llm.py`](app/backend/services/agent_llm.py) 负责模型代理。

## 后续扩展与优先级

1. **P0：稳定交付。** 完善鉴权、限流、补丁定位和版本保存一致性，补齐登录到真实保存、刷新恢复、分享导出的回归验证。先保证现有流程可靠。
2. **P1：提升生成质量与过程控制。** 增加典型业务验收用例、取消生成，以及耗时、模型用量和修复次数统计，让质量与成本可衡量。
3. **P2：扩大应用范围。** 支持后台任务与恢复，再引入多文件工程和模型选择；同步调整预览、检测、版本和导出，保持完整体验。
